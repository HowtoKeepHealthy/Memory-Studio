# Memory Studio

Windows x64 进程内存工作台，C++20 扫描核心 + C# / .NET 10 WPF 界面。提供中文深色与纸白中国风主题，支持结果分页、后台扫描和离线地址分析。

## 直接运行

双击桌面的 **Memory Studio** 快捷方式、根目录的 **run.cmd**，或运行 **artifacts/release/MemoryStudio.exe**。发布成品是普通目录结构，已包含 .NET 桌面运行时，使用时无需另外安装 .NET。移动或复制成品时，请保留整个 **artifacts/release** 文件夹中的 EXE、DLL 和运行时文件。

1. 从顶部列表选择进程，点击“连接进程”；也可以按住列表旁的准星，拖到目标程序窗口后释放。拖动时会显示窗口标题、进程名和 PID，并高亮目标边框；按 Esc 可取消。桌面、任务栏和 Memory Studio 自身不会作为拾取目标。
2. 点击“启动练习进程”可自动连接内置的 DemoTarget，按其提示练习扫描和修改。
3. 选择数据类型、扫描方式和值，点击“首次扫描”。支持精确、未知初始值、大于、小于、闭区间；再次筛选另支持变化、未变化、增加、减少及指定增减量。不需要输入数值的方式会禁用数值框，闭区间启用上下限两个框。浮点默认使用绝对/相对容差，字节模式可输入 `48 8B ?? A? ?F`。
4. 选择结果并点击“添加到地址表”，或在右键菜单中添加。双击地址、当前数值、类型列会打开对应编辑窗口；地址表的描述列也支持双击编辑。冻结框单击切换，双击编辑冻结值。冻结会每 500 ms 恢复所记录的数值，取消勾选即可停止。
5. 结果表和两个地址表都支持 Ctrl/Shift 多选。扫描结果中的 Ctrl+A 或“全选全部”会加载并选择本次扫描的全部结果，包括其他分页；“全选本页”只选当前已显示的结果。未知初始值快照超过 200 万候选时需继续筛选后才能全选全部，当前页仍可选择。地址表中的 Ctrl+A 或“全选”选择全部监视地址。
6. 双击当前焦点行保留多选范围，按数值/类型列批量编辑；普通点击其他行改为单选，点击空白取消选择，Ctrl/Shift 继续用于多选。右键已选行保留整组选项。“写入”按钮对当前地址表的整个选择范围生效；数值输入框及操作按钮保留选择，便于先输入再批量写入。地址编辑、内存查看、反汇编和访问追踪以单条记录为入口。
7. “内存查看”支持地址跳转、实时字节与 ASCII、按字节编辑和撤销。“反汇编”围绕指定指令显示上下文，滚动到边缘会连续加载，支持 x86/x64、汇编补丁、原始字节补丁、NOP 及撤销。补丁汇编使用内置 NASM，按目标地址生成相对跳转；写入前会预览字节，扩长补丁会影响后续指令，须检查覆盖范围。
8. 工具菜单可手动加入绝对地址、模块表达式或指针链；指针偏移从根到目标排列。地址表可保存为 .mstable v2，兼容读取 v1；也可导入/导出 .CT 地址和指针数据，脚本条目会跳过。加载默认不启用冻结。
9. 选中记录后右键“撤销所选记录”、点击地址表的“撤销所选”或在表格中按 Ctrl+Z，可分别撤销每条所选记录的最近一次修改，包括数值和记录属性；同一次批量编辑中未选中的记录会保留。连续撤销可逐条回退自己的历史，跨结果分页也保留历史。目标自行改变数值后仍会写回本次编辑前的值；已记录的后来重叠写入或代码补丁须先撤销，失败项保留供重试。内存/反汇编窗口的撤销恢复本窗口共享写入历史中的最近补丁。内存编辑历史按同一目标共享，通常最多 100 组/32 MiB，单次超大批量保留一整组；记录属性另保留最近 100 组。冻结维护不产生历史，撤销会同步冻结值。
10. 工具菜单的“撤销上次扫描”恢复候选地址及其比较快照，最多 16 步；普通结果和历史元数据受 64 MiB 内存预算约束，未知初始值历史文件另有 4 GiB 软预算，保留最近一份可撤销快照。
11. 工具菜单的“显示与窗口设置”可切换“深色工作台 · 青绿”和“宣纸墨色 · 朱砂与青玉”，整体缩放为 60%–150%、字号为 10–20，并记住主题和各窗口大小；Ctrl+滚轮调整缩放。纸白主题采用暖白纸色、墨色文字、朱红按钮和宋体标题，浏览窗口及右键菜单同步切换。主窗口最小为 780×520，扫描条件始终在结果旁边；小窗或较大缩放时使用页面横纵滚动。拉高窗口时，扫描页下方的地址表与单独地址表页都会增加可用高度。
12. 搜索/写入支持十进制与十六进制切换，切换时转换已有数值；浮点十六进制是 IEEE 754 位模式。暂停/恢复控制目标线程，保留外部调试器已有的挂起计数，正常退出或切换进程会恢复本工具暂停的线程。

演示进程初始生命值 **100**（4 字节整数）、金币 **2500**、速度 **1.25**（单精度）。演示窗口按 H 减少生命，G 增加金币，S 增加速度，R 重置，P 打印，Q 退出。

## 查找读写来源

在扫描结果或地址表中右键单个地址，选择“查找写入来源”或“查找访问来源（读取/写入）”，然后点击“开始追踪”，并在目标程序中触发数值的使用或变化。列表显示触发指令的地址、机器码、反汇编、线程和捕获次数；选择一行可查看该指令执行前的寄存器快照。

“写入来源”记录执行写入的指令；“访问来源”包含读取和写入，读改写指令会标为“读取 / 写入”。监控使用 Windows 调试附加和临时页面保护，按实际指令操作数的地址与宽度排除同一页上的无关访问，支持 x64 和 WOW64 目标。

内存、反汇编、结构、指针扫描和来源追踪均是独立浏览窗口，主窗口可继续操作。追踪活跃时仅跳过监测保护页的读写/冻结，原生核心同样排除这些页，包含临时重新布防的间隙；其他地址继续更新。点击“停止并保留结果”后监视恢复，双击捕获行会先停止并确认脱离，再同时打开该指令的反汇编和触发地址内存。编辑/写入的短对话框保持模态。

关闭追踪或退出主程序会先恢复页面保护并解除附加，失败会保留窗口供重试；重新开始会清空上一次捕获。同一进程同时只允许一个追踪会话。目标程序可能变慢，捕获次数不等于程序全部访问次数；高频访问、内核访问或外部工具读写可能丢失事件，窗口会显示状态及丢弃数。已有调试器、权限不足、地址失效或页面已有保护监控时会显示具体错误。

## 分析地址与导出 AI 上下文

在结果或地址表中右键单条记录，选择“分析地址 / 导出 AI 上下文”；也可从反汇编或来源追踪窗口点击“分析 / 导出”。窗口保持独立，整理当前数值和字节、模块及 RVA、页面属性、附近指令、寄存器读写与内存操作数，并提供常见汇编语句的中文解释。

建议先追踪实际访问，选中一条捕获指令，再打开分析窗口。分析会先安全停止活跃追踪并保留捕获，纳入与同一进程、所选地址范围匹配的证据，包括触发指令、机器码、寄存器、访问宽度和捕获次数。静态解码与实际捕获分别列出，数据附近的指令明确标记为推测边界。反汇编入口使用所选指令作为已知边界；这本身不证明该指令访问了数据。

可导出 Markdown、JSON，或点击“复制给 AI 的提示”，把汇编及相关证据交给 AI 解释字段、地址计算和可能的逻辑，再用追踪验证假设。报告只在本机生成，不自动调用 AI；它提供汇编上下文而非还原 C/C++ 源码。JSON 中地址和寄存器使用十六进制字符串，保留 64 位精度。分析是分步读取的快照，目标运行时数据与代码可能继续变化。

## 功能与边界

- 支持 1/2/4/8 字节整数、单/双精度浮点、UTF-8、UTF-16 和带整字节/半字节通配的字节序列。
- 数值支持未知初始值；字符串/字节支持精确、变化和未变化筛选，再次扫描保持原来的类型和长度。
- 可限定十六进制地址范围，起始与结束地址均包含在范围内；一个数值的所有字节须在范围内。默认起始为 0x00000000，结束按 x86/x64 用户地址空间预填为 0xFFFFFFFF / 0x00007FFFFFFFFFFF，连接进程时保留手动指定的范围。原生 C ABI 仍使用结束地址不包含的范围，界面会自动转换。
- 普通首次扫描结果上限为 2,000,000。未知初始值及从该快照开始的后续筛选使用分块临时文件和候选位图，可保留超过该上限的候选；单份快照文件上限 16 GiB，元数据上限 64 MiB。临时文件使用系统临时目录，释放会话或淘汰历史时自动删除。预算不足、文件写入失败或取消均保留上次成功的结果和撤销历史。
- 结果通常每页 200 条，候选地址与比较快照留在 C++ 核心；跨页全选后临时停用翻页。可见结果与地址表每 500 ms 刷新，不重置选择；扫描及批量处理期间暂停主表刷新。超大地址表受实际读写耗时影响。
- 指针扫描支持 1–5 层、自然对齐指针和非负偏移，优先搜索模块根。每层预算 512 MiB、候选节点上限 100,000、结果上限 10,000，触及预算会明确标为截断；可重新校验。结构工具按字段解释内存并支持类型/数值编辑。
- 未加入 Lua/自动汇编脚本、训练器、Mono/.NET 对象检查、DBVM/内核驱动模块。时间倍率钩子未加入，本版提供暂停/恢复。来源追踪提供访问快照而非通用单步调试器。
- 启动会尝试 UAC 管理员提权，取消后仍可普通运行。自动测试与截图不触发 UAC；`--no-elevate` 可显式跳过提权。访问失败会显示具体错误。

## 开发环境

项目内已配置 **.NET SDK 10.0.401**、**llvm-mingw 20260922 / Clang C++20** 和 **NASM 2.16.03**。固定版本工具在 .tools，编译器和汇编器下载校验 SHA-256；成品嵌入 NASM，不要求用户安装开发工具。

- 双击 **build.cmd**：构建 C++ 核心、演示进程、测试程序并发布完整 WPF 应用。
- 运行 **build.cmd -Test**：构建后执行 native 和 managed/界面工作流集成测试。
- 运行 **package.cmd -Test**：验证并发布普通目录版，包含使用说明和第三方许可，同时创建或更新桌面快捷方式。
- 双击 **dev.cmd**：打开已配置 dotnet 和 clang++ 路径的项目终端。
- IDE 可打开 **MemoryStudio.slnx**。核心 C ABI 定义位于 native/memory_core.h。

工具链缺失时构建脚本会下载项目内的固定版本工具。产物位于 artifacts/release，测试报告位于 artifacts/managed-test.txt。构建原生核心也可单独运行 scripts/build-native.ps1。

## 结构

| 目录 | 内容 |
| --- | --- |
| app | WPF 界面、MVVM、C ABI 调用和监视服务 |
| native | Win32 进程访问、内存扫描、快照筛选、C ABI |
| tests | 真实页内存集成测试与演示目标 |
| scripts | 便携工具链安装和构建脚本 |
| artifacts | 编译产物、运行成品、验证报告及界面预览 |
| .tools | 项目内 SDK 和编译器 |

扫描失败和取消采用事务性提交；C ABI 不跨边界抛异常。UI 与核心通过批量分页传输地址，扫描和内存查看在后台执行。
